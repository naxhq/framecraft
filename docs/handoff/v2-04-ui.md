# v2-04 — the editor redesign, v2 controls and hero picking

Scope: `apps/web/**` only. `apps/web/lib/transform.ts`, `apps/web/lib/transform.test.ts`,
`fixtures/parity-*.json`, `packages/contracts/**` and `apps/web/lib/contracts.ts`
were **not** touched (the mesh-bake / parts-export phase owns those and was
editing them concurrently). One test file outside that set changed:
`apps/web/lib/preview.test.ts`, and only to make an assertion stricter (§9).

---

## 1. What was wrong, and what each fix is

| Defect | Fix |
|---|---|
| Six lines of stacked orange text in the sidebar | One chip, "N adjustments made", opening a grouped scrollable drawer. Blocking warnings stay on screen as banners. |
| Generate and Bake as two equal buttons; Generate always clickable | Primary/secondary swap on whether a scene exists; Generate carries a real `disabled` attribute when the scene is already current. |
| One flat list of ~20 controls | Seven collapsible groups, collapse state persisted, bodies unmounted when closed. |
| Predicted height and scale buried in a text chip | A spec strip across the bottom of the viewport: **scale · height · min wall**. |
| Raw hex colours scattered through components | A `--fc-*` token set in `app/globals.css`, mapped through `@theme inline`; a vitest fails on any hex elsewhere. |
| System font stack | Two self-hosted OFL faces, no Google font request at runtime. |
| "Pick a location or a preset, then click Generate." as the whole empty state | A real empty state, a skeleton during fetch, a determinate bake bar. |
| No keyboard affordances | G / B / R / ? / Esc, ignored while typing, with a shortcut sheet. |
| Layout collapsed to one broken column under `lg` | Bottom sheet from 640, "desktop recommended" below it. |

## 2. The token set

`apps/web/app/globals.css` is the only file in the app that may contain a
colour. Everything else uses the Tailwind utilities generated from it.

**Where the palette comes from.** Not invented: it is the product's own default
filament set (DECISIONS [V2-P2]) pulled up into the interface — base/buildings
warm grey `#D8D3C6`, roads/frame charcoal `#3A3A3A`, water `#2F7FC1`, planting
`#5A9E4B`. The editor is made of the same materials as the object it designs.
Light is "bench, daylight" (putty paper, charcoal ink, a harbour blue for
selection); dark is the same bench at night.

```
surfaces   --fc-bench  --fc-plate  --fc-plate-raised  --fc-plate-sunken
rules      --fc-line  --fc-line-strong                       DECORATION only
boundaries --fc-control-border(-strong)                      controls, >= 3:1
type       --fc-ink  --fc-ink-muted  --fc-ink-faint          (13.7 / 7.9 / 5.3 : 1)
action     --fc-primary(-hover,-ink)                          stamped charcoal
selection  --fc-accent(-hover,-ink,-soft)  --fc-focus         harbour blue
states     --fc-positive(-soft)  --fc-warn(-soft)  --fc-danger(-soft)
preview    --fc-preview-{bg,base,frame,building,road,water,green,tree,grid,
                         hero,cursor,sky,bounce}
map        --fc-map-{pin,pin-ring,radius-fill,radius-line,crop,marker-shadow}
                                                              (:root only)
elevation  --fc-shadow-{flush,raised,lifted}
```

The `rules` / `boundaries` split is WCAG's, not a preference: SC 1.4.11 wants
3:1 for the visual boundary of a control and says nothing about a divider. A
control that reaches for the hairline is the defect `lib/contrast.test.ts`
exists to catch.

Mapped in `@theme inline` to `--color-*`, `--font-{display,ui}`,
`--text-{2xs…2xl}` (+ line heights), `--radius-{milled,plate,panel}` (3/5/8 px —
a milled chamfer, not a pill and not a zero-radius broadsheet),
`--shadow-{flush,raised,lifted}` and `--spacing-{rail,atlas}` (the two column
widths, stated once). `inline` is load-bearing: it emits `var(--fc-*)` into the
utilities, so the `.dark` class re-points every one of them at once.

The 3D preview and the MapLibre overlays read the same tokens at runtime
(`components/scene/palette.ts`, `components/map/palette.ts`), both falling back
to the CSS keyword `magenta` so a missing token is obvious rather than
plausible. In `color_mode: "parts"` the preview paints with the user's
`part_colors` instead; the background and ground grid stay themed.

**Contrast.** Three inks and the positive green were moved from the first draft
purely to clear WCAG AA on the surfaces they actually sit on, and the control
boundaries again after the audit — see DECISIONS [V2-P4] and [V2-P4-fix].
Verified by computing the WCAG formula over this file in `lib/contrast.test.ts`
(text 4.5:1, boundaries 3:1, both themes) **and** by axe for everything axe can
see (§7). Neither on its own is enough: axe does not implement SC 1.4.11.

## 4. The seven groups

`lib/groups.ts` owns the table; `components/editor/groups/*` own the bodies.

| Group | Contents | Default |
|---|---|---|
| Location | coordinate readout, **city_label** (labelled as the `{city}` token), radius, rotation | open |
| Scale and size | plate, base thickness, nozzle, + a derived "1:10,714 · 0.80 mm minimum wall · 168 mm usable" line | open |
| Buildings | small/large scale, **hero list** (removable, `n/12` badge, "the list is full" notice) | open |
| Surface | road mode, road scale, water, trees, terrain | open |
| Frame and text | frame, **engravings editor** (≤8: text ≤64 with a live token expansion, edge, align, mode, cap height, depth, font), **north arrow** (enabled/corner/size), **scale bar** (enabled/edge/mode/length), **underside mark** (enabled/template + live expansion), **hanger** | collapsed |
| Colour | **color_mode**, the **seven part_colors** wells (native `<input type=color>`, hex shown, disabled in single mode), **hero_mode** | collapsed |
| Output | the action row, bake status + progress, download links, print stats | open, **pinned** |

Every bound comes from the generated `PARAM_RANGES` (including the nested
`engravings.size_mm`, `north_arrow.size_mm`, `scale_bar.length_m`) and every cap
from the generated `PARAM_LIMITS` — `HERO_CAP` (12), `ENGRAVING_CAP` (8) and the
three 64-character `maxLength`s with their counters. No limit is re-typed at a
call site.

Every write goes through `store.setParam`, or `store.setNested`, which is
`setParam` with an immutable spread — so bake staleness, `previewDeps` and the
"no server call on a parameter change" guarantee all keep working unchanged.
The store's initial params and `resetParams` both call `defaultPrintParams()`:
`DEFAULT_PRINT_PARAMS` is deep-frozen, and a shallow spread would alias its six
nested v2 objects into live state where the first write would throw.

Collapse state persists in `localStorage` (`framecraft-groups`) with try/catch
on read *and* write, merged over the defaults; a corrupt, missing or partial
value renders the panel open. Collapsed groups unmount their body.

## 5. Keyboard map

| Key | Action |
|---|---|
| `G` | Generate (no-op when the scene is already current, like the button) |
| `B` | Bake (no-op while baking or while a block reason stands) |
| `R` | Reset every parameter |
| `?` (or Shift+/) | Shortcut sheet |
| `Esc` | Close the drawer, then the sheet — from anywhere, whatever has focus |
| `← →` etc. | Native range nudge; still commits through the 250 ms gate on release |
| `← →` in the preview | Move the building cursor (tallest first); `Enter`/`Space` picks it as a hero; `Home`/`End` jump |

Ignored on every modifier chord and whenever the target accepts text. A
`type="range"` is deliberately not a typing target. The sheet is a real modal:
focus moves in, Tab is trapped, focus returns on close — and **G/B/R do not
reach the editor behind it**, which they used to.

**The hero cap is answered twice, on purpose.** The Buildings group states the
*state* ("that is the limit: 12 hero buildings") whenever the list is full; the
viewport shows a `role="status"` notice (`hero-cap-hit`) when a click is
actually *refused*, because that group may be collapsed and a click that
silently does nothing reads as a bug. The store flag behind it (`heroCapHit`,
set on refusal and cleared by the next successful toggle) is covered by
`store/editor.test.ts`; the viewport notice itself has no e2e, because driving
it needs twelve distinct successful raycast picks and that test would be flaky.

## 6. Empty, loading, progress

- **Empty** (`preview-empty`): eyebrow, display headline, the four steps in
  order, and the keyboard hints — on the drafting-sheet grid.
- **Loading** (`preview-skeleton`): a plate-shaped skeleton, `role="status"`,
  "Fetching the scene from OpenStreetMap…".
- **Bake** (`bake-progress`): determinate from `BakeResult.progress`, with
  `data-determinate`/`data-progress` and `aria-valuenow`; indeterminate only
  while progress is null (i.e. between the click and the first poll).

## 6a. After the audit

`docs/handoff/v2-04-audit.md` found 16 defects (5 major); all 16 are fixed and
its §5 Resolution lists each one with its regression test. The five that changed
behaviour described elsewhere in this document:

- **Shortcuts are suppressed while an overlay is open.** With the sheet open, B
  used to start a real bake behind the modal and R used to reset everything.
- **Control boundaries are their own token family** (`control-border`,
  `control-border-strong`) at ≥ 3:1 (SC 1.4.11), separate from the decorative
  hairline. axe does not implement that criterion, so `lib/contrast.test.ts`
  computes it from the token file — 23 text pairs at 4.5:1 and 12 boundary
  pairs at 3:1, both themes.
- **Hero picking has a keyboard path**: the viewport is a focus stop and arrows
  walk a building cursor (tallest first), Enter toggles. WCAG 2.1.1 Level A.
- **Escape closes the drawer from anywhere**, and hands focus back to the chip.
- **The tab walk is real** — 120 Tab presses, 44 distinct controls, every one
  with a visible focus ring (including MapLibre's own three, which shipped
  ringless).

## 7. Accessibility results

`e2e/a11y.spec.ts`, axe-core via `@axe-core/playwright` 4.13.0, failing on
`serious` or `critical`. Nothing is skipped and no rule is disabled.

| State | light | dark |
|---|---|---|
| empty | 0 violations, 40 passes | 0 violations, 40 passes |
| Chicago generated, every group open | 0, 39 | 0, 39 |
| adjustments drawer open | 0, 41 | 0, 41 |
| shortcut sheet | 0, 42 | 0, 42 |

axe is necessary and not sufficient: it does not implement SC 1.4.11, so the
non-text contrast floor is asserted by `lib/contrast.test.ts` instead, and
reachability is asserted by a real Tab walk rather than by axe.

`incomplete` is 1 node in every state and is reported, not asserted: the
translucent map hint over the raster tiles, where a static checker cannot
resolve the backdrop. Two real defects were found and fixed by this run: a
`heading-order` jump in the drawer (h4 → h2), and the contrast of the three ink
tokens plus the positive green. A third "failure" was a measurement artefact —
axe auditing mid theme cross-fade — and is handled by settling before the audit,
not by loosening the assertion.

A second test enumerates every interactive control and fails on any without an
accessible name: **0 unnamed, 52 keyboard-reachable controls**.

## 10. Verify

```sh
cd apps/web && npm test -- --run && npm run typecheck && npm run lint
cd apps/web && npm run test:e2e       # starts uvicorn :8000 + next dev :3000 itself
cd apps/web && npm run build          # LAST, and only with no dev server alive
```

Last run: 300 unit tests in scope, typecheck clean, lint clean, **19 e2e
passed**, build clean.

**The order matters and the old §10 had it wrong.** `next build` and `next dev`
share one `apps/web/.next` — there is no per-run dist dir — so building first
leaves a tree the dev server that `test:e2e` starts cannot serve
(`Cannot find module .../.next/server/app/page.js`, then a Fast Refresh full
reload that `smoke.spec.ts`'s navigation counter sees as an 01/A3 failure).
Either run `test:e2e` on its own, or `rm -rf .next` between the two, or use
`FRAMECRAFT_WEB_MODE=prod npm run test:e2e`, which serves the build instead of
racing it. The same constraint is written at the top of `playwright.config.ts`.

All four green on this host. `make gate` and `make up` were not run (not this
phase's to run).
