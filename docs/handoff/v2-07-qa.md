## 1. What `make gate` means now (G7)

`make gate` is the same command it was at G4 — the whole product, in one
process, never leaving a stack up — with three new failure conditions, all of
them about *tests that did not run*. It is now seven steps:

| Step | What | Fails the gate when |
|---|---|---|
| 0/7 | `make down` | never (the gate owns the lifecycle) |
| 1/7 | **static no-skip guard** over every `*.test.ts(x)` and `*.spec.ts(x)` under `apps/web` (31 files) | any `test/it/describe/suite/bench` `.skip`/`.only`/`.fixme`/`.todo`/`.skipIf`/`.failing`, or `xit`/`xtest`/`xdescribe`, is committed; also when the glob matches **no** files |
| 2/7 | `uv run pytest -q -rs` (services/bake), logged to `artifacts/logs/pytest.log` | non-zero exit, **or** the summary reports any `skipped` / `xfailed` / `xpassed` |
| 3/7 | `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` — each attributed separately | any one of them fails, or the vitest summary reports `skipped`/`todo` |
| 4/7 | chromium present | not installed (prints the `npx playwright install` hint) |
| 5/7 | `make up` (redirected to `artifacts/logs/up.log`) → `npm run test:e2e` | suite fails, **or** `artifacts/e2e/results.json` `stats.skipped != 0` |
| 6/7 | `make down`, then a port probe on 8000 and 3000 | `make down` fails, or either port still listens |
| 7/7 | `git status --porcelain -- fixtures/` | a `fixtures/<40-hex>.json` survived the e2e (or `git` is not on PATH) |

**Zero skipped tests is asserted in four independent places**, and none of them
is redundant, because both pytest and Playwright exit 0 on a skip:

1. static, at step 1 — catches a marker somebody committed;
2. pytest's own summary, at step 2 — catches a runtime `pytest.skip` / `skipif`
   / `xfail`;
3. vitest's summary, at step 3;
4. `results.json` `stats.skipped`, at step 5 — the whole Playwright suite, not
   a per-file sample: Playwright's JSON reporter aggregates every project and
   every spec file into one `stats` object, so a skip anywhere shows up there.

`next build` still runs *before* `make up`, per DECISIONS `[P4]`: building into
`.next` while `next dev` serves it corrupts the dev server and produces a bogus
extra navigation that `smoke.spec.ts`'s `watchNavigations` counts.

### The two skips that existed, and what happened to them

* **`apps/web/e2e/smoke.spec.ts:546`** — `test.skip(status === 502 || 503,
  "Overpass is unreachable from this host")` in the A2 low-coverage test. This
  was **replaced by a plain failing assertion** carrying the same two
  diagnoses (Overpass unreachable; `FRAMECRAFT_OFFLINE` was set). That is
  *strictly stronger*, not weaker: the gate already failed on any skipped test,
  so the skip only changed the wording of a failure that was going to happen
  anyway — and one conditional skip in the tree makes step 1's guard impossible
  to state without a carve-out. `playwright.config.ts`'s comment about "the only
  skip in this suite" was corrected with it.
* **`services/bake/tests/test_validate_cli.py:510`** —
  `@pytest.mark.skipif(not (ARTIFACTS / "chicago.3mf").is_file())` on
  `test_cli_passes_on_the_chicago_fixture_bake`, i.e. G3's own command. It never
  fired on this host (the artifact exists) but it deleted G3's assertion from the
  suite on a **clean clone**, which is the machine where it is worth the most.
  Made unconditional: a session fixture bakes `artifacts/chicago.3mf` with the
  same call `make bake-fixture` makes if it is not there. No test was deleted or
  loosened; nothing was reported to FAILURES.md for it.

  **Superseded by [V2-P7-fix].** "If it is not there" was still a false green:
  on any host that had ever run `make bake-fixture` the test asserted about a
  pre-existing file, and `PLATE=` used to change the parameters without changing
  the stem, so `artifacts/chicago.3mf` could be a 256 mm bake whose sidecar said
  256 and which therefore passed (v2-07 audit, finding 1). The fixture now bakes
  **unconditionally**, at `PrintParams()` defaults, into `tmp_path_factory`, and
  never touches `artifacts/`; it also asserts the header names the default plate.

Verified the guard is not vacuous: a probe file carrying `it.skip`, `test.only`,
`test.todo`, `test.fixme`, `test.describe.skip` and `xit` was written into
`apps/web/lib/`, and all six lines were reported by step 1 (the probe was then
deleted). The fixtures check was verified the same way, by planting
`fixtures/0000…0000.json` and watching step 7 name it. The pytest summary check
was verified against a synthetic `590 passed, 1 skipped` line (caught) and a
clean `591 passed` line (not flagged).

**The `results.json` check proved itself on live evidence.** The first
authoritative gate run of this phase hit a real spec failure (F2, §4). Because
`ui.spec.ts` is `mode: "serial"`, the 12 tests after it did not run — and
Playwright reports "did not run" as *skipped*. Step 5 printed
`gate: 12 Playwright test(s) SKIPPED` and failed the gate on that as well as on
the failure itself. That is the whole-suite coverage the brief asked to have
verified: the check saw 12 of the 25 acceptance tests silently not run, in a
file the failure was not even in.

### (a) the north arrow, measured out of the finished solid

The existing `test_ornament_north_arrow_points_at_true_north` checks the
*layout*'s `placement.rotation_deg`. This one never reads it. It bakes the real
Chicago SceneGraph — the committed Overpass fixture through the real ingest —
through `app.bake.run_pipeline` with `rotation_deg = 29.0`, loads the exported
`.3mf`, takes a horizontal section through the frame lip at
`base_top + FRAME_LIP - ENGRAVE_MAX/2` (4.7 mm), lifts the one small interior
ring out of the plate-wide band polygon, and recovers the arrow's compass
bearing by rotational alignment against the nominal glyph (1° sweep then 0.05°,
IoU must exceed 0.4 or the test says the cut is not the arrow). The expectation
comes from `app.geom.project.LocalFrame` alone: a point 0.01° due north of the
scene centre, projected, read as `atan2(x, y)`.

Measured: the arrow is cut at bearing **330.9°**; `project.py` puts true north
at **331.4°**; error **0.5°**, tolerance 2° (UTM meridian convergence). The test
also asserts the *wrong* sign is more than 20° away, so it cannot pass
vacuously — the shipped `-rotation_deg` bug is 57.7° out here.

One convention had to be pinned down and is now documented in the helper:
`lettering.place(θ)` rotates **counterclockwise**, so a glyph whose apex is at
`(0, +size/2)` lands at compass bearing `-θ`. Comparing a `place` angle directly
with a bearing is off by a sign; the helper returns the bearing.

### (b) frame off + emboss

`test_bake_with_the_frame_off_ships_no_floating_letters` already asserts the
in-process report. The new test asserts the **files on disk**: the shipped
`app.cli validate` over both the `.3mf` and the `.stl`, `bodies PASS` with the
value starting `1 `, `ALL CHECKS PASS`, and exactly one warning containing
"the frame is off" and "turn the frame on". The bake **refuses** the lip
features (it does not silently skip them) and the model is byte-comparable in
bbox and volume to one that asked for no text at all.

### The one real defect the review found (F2)

`ui.spec.ts:an engraving appears on the frame, and a refused one does not` was
taking the size it asserted **about** from the contract default: it added a row,
inherited whatever cap height the contract seeded, and required the panel to say
`Not cut`. `[V2-P5-fix]` then raised `engravings[].size_mm` from 3.0 mm to
4.0 mm *precisely so that a freshly seeded engraving is printable*. The test had
silently become "the default is refused" — the opposite of what the contract now
promises — and it failed the first authoritative `make gate` of this phase with
`Expected "Not cut", Received "Cuts at 4.00 mm."`, taking 12 more serial tests
down with it (1 failed, 12 not run → `stats.skipped = 12` → GATE FAIL, which is
the new step-5 check doing its job).

Measured against the shared math on this tree: `Chicago` is refused at 2.0, 2.5
and 3.0 mm and cuts from 3.25 mm up. The application is correct; the spec was
stale. Fixed by naming both sizes: pin 4.0 mm as *cutting* (rings drawn), then
3 mm and require `Not cut` **and the rings to fall back to 0**, then 6 mm and
require exactly 8 again. Strictly more coverage than before — the preview is now
proved to take the letters *off* the plate when the verdict flips. Written up as
**F2** in `docs/handoff/FAILURES.md`.

Rule adopted from it, in DECISIONS: *a test may not take the value it is
asserting about from a contract default.* The default is what the contract is
free to change; the assertion is what must not.

## 6. FAILURES.md

One entry added: **F2 — `e2e/ui.spec.ts` asserted a premise `[V2-P5-fix]` had
already deleted** (§4 above). Owner qa-gate, status FIXED here, **no application
code at fault**. It is recorded rather than quietly fixed because it is the
reason the V2-P6 handoff's "25 e2e, 0 skipped" and this phase's first gate run
disagree, and the next reader should not have to re-derive that.

No application defect was found **by this phase**; the independent audit that
followed it found one, and [V2-P7-fix] fixed it: the editor never called
`transform.underside_min_base_mm`, so `hanger = keyhole` on the default 3 mm
base was offered and only refused by the bake (v2-07 audit, finding 4). It is a
`block` warning in `apps/web/lib/warnings.ts` now, exactly like
`model-too-tall`. Three things that looked like candidates *were* checked here
and are qa-gate's own, fixed without touching application code:

* the `skipif` on G3's assertion (a test-file change),
* the conditional `test.skip` in `smoke.spec.ts` (a spec change), and
* F2 (a spec change).

The hanger-minimum arithmetic (3.6 / 4.7 rather than the brief's 3.0 / 4.1) is
**not** a defect either: `underside_min_base_mm` correctly composes the pocket
depth, the 1 mm roof and the deepest top-side recess, exactly as `[V2-P5]`
describes. The brief's 3.0 / 4.1 are `hanger_min_base_mm` alone, which is the
wrong number to refuse on when the roads are engraved.
