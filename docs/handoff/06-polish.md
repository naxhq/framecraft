## 1. F1 — `npx tsc --noEmit` failed on a test file

`lib/warnings.test.ts:179` cast `PrintParams` straight to
`Record<string, unknown>`; `PrintParams` has no index signature, so TS2352
wanted the double hop. The cast now goes through `unknown`. The assertion
around it (every PrintParams key that moves the height prediction must be in
`warningDeps`) is unchanged.

The defect's real lesson was that **nothing in the gate type-checked the
project**: `next build` only type-checks the app graph, `eslint .` is not
type-aware, and vitest transpiles without checking, so a type error in a test,
an e2e spec or an unreached module was invisible until an editor opened it.

- `apps/web/package.json` gained `"typecheck": "tsc --noEmit"`.
- `make gate` step 2 is now `npm run lint && npm run typecheck && npm test &&
  npm run build`.

`docs/handoff/FAILURES.md` F1 is marked FIXED with the verification command.

## 2. The `/favicon.ico` 404 on every page load

Confirmed from the P4 session's own capture,
`.playwright-mcp/console-2026-08-29T15-52-37-562Z.log`:

```
[ERROR] Failed to load resource: the server responded with a status of 404
        (Not Found) @ http://localhost:3000/favicon.ico:0
```

Added, via the App Router metadata file convention:

- `apps/web/app/icon.svg` — a framed-city glyph (dark tile, light frame, three
  building blocks on a base bar), hand-written SVG.
- `apps/web/app/favicon.ico` — the same glyph rasterised to a 32×32 32-bit
  PNG-in-ICO (170 bytes), generated by a throwaway stdlib script (zlib + CRC by
  hand, no new dependency) which was deleted afterwards, the same way
  `fixtures/chicago-scene.json` was produced in P1.

Both are needed: the `<link rel="icon">` covers browsers that honour it, and
the real `/favicon.ico` covers the bare guess Chromium made above. Verified
served from a clean clone: `favicon.ico=200 icon.svg=200`, and the document
now carries

```
<link rel="icon" href="/favicon.ico" type="image/x-icon" sizes="32x32"/>
<link rel="icon" href="/icon.svg?bbd94387ceae64e4" type="image/svg+xml" sizes="any"/>
```

The e2e now fails on a 404 for either name, and asserts the document declares
an icon at all.

## 3. A finished bake was never invalidated

Baking, then moving any slider, left the stats card and the download links
advertising a file built from the old parameters — the direct opposite of 01's
"the preview and the printed result agree".

- `BakeState` gained `stale: boolean` (`lib/bake.ts`), plus
  `markBakeStale(state)` (terminal bakes only, identity-stable when nothing
  changes), `bakeDownloadLinks(state)` (empty while stale) and the shared
  string `BAKE_STALE_NOTE`.
- `reduceBake` sets `stale: false` — a response off the wire is current by
  definition — so the next bake clears it automatically.
- `store/editor.ts` marks it from `setParam`, `resetParams`, `setPin`,
  `setRadius`, `setRotation`, `applyPreset` and a successful `generate()`.
- `BakeButton` hides the download links and shows
  "Parameters changed since this bake — bake again to download a matching
  file." (`data-testid="bake-stale-note"`); the status row reads
  "Done (outdated)". `StatsCard` keeps the numbers but retitles itself
  "Print stats (previous bake)" over the same note.

Tests: 4 pure-function cases in `lib/bake.test.ts` and 6 store-transition cases
in `store/editor.test.ts` (including one that walks **every** PrintParams key),
plus e2e step 11, which moves a slider after the real bake and asserts the
links disappear with no new server call.

## 4. The preset chip lied after a reload

`INITIAL_LOCATION.preset_id` is `"chicago-loop"`, and `PresetRow` read
`location.preset_id` directly, so a fresh load highlighted Chicago with no
scene behind it.

New selector `activePresetId(state)` in `store/editor.ts`: the id is returned
only when `scene.graph !== null` (a scene really is loaded) **or**
`presetChosen` (a new store flag, set by `applyPreset`, cleared by `setPin`).
A preset click therefore lights up immediately, before its scene arrives, and a
failed Generate at the initial location leaves every chip dark. 5 tests.

## 5. `app.cli validate` crashed on a bad sidecar

`_params_from_sidecar` fed the sidecar's `print_params` straight into
`PrintParams(**data)`, so a value outside the FROZEN contract came out as a
`pydantic_core.ValidationError` traceback with no table and no verdict.

It now returns `(params, source, error)`:

- an unusable sidecar — unreadable, not JSON, no `print_params` object, or
  values the contract rejects — yields a `sidecar_params` **FAIL** row reading
  `sidecar params invalid: <field>: <reason>`, a matching header line, and exit
  code 1;
- the mesh is still judged, against `--plate-mm` / `--nozzle-mm` if the caller
  gave them, else the contract defaults, and the `parameters` header says which
  ("command line" vs "sidecar x.json" vs "sidecar x.json + command line");
- an override lands *before* validation, so `--nozzle-mm 0.4` can repair the
  one field a sidecar got wrong and the run goes back to green;
- an override the contract itself rejects (`--plate-mm 5000`) is a usage error
  on stderr with exit code 2, checked before the mesh is even loaded.

12 new tests in `services/bake/tests/test_validate_cli.py`, including one that
runs the real subprocess and asserts no `Traceback` and no `ValidationError` in
the output.

## 6. `make gate` swallowed its own teardown

The final `$(MAKE) down ... || true` could not fail the gate, and nothing
checked the ports. Since [P1-fix] a survivor on :8000/:3000 makes the *next*
`make up` a hard error, so a silently-failed teardown turned into a confusing
failure one run later.

The gate now has an explicit step `[5/5] teardown (always attempted, and
checked)`: the teardown always runs, a non-zero `make down` fails the gate with
the last 20 lines of `artifacts/logs/down.log`, and a `port_listening()` helper
(netstat `LISTENING` on Windows, plus a `curl` probe of `/` and `/health` on any
host) fails the gate naming the ports that survived. Steps are renumbered
`[0/5]`..`[5/5]`. Positive control: the helper reported
`busy=[ 8000 3000]` while the stack was up and `busy=[]` after `make down`.
