# v3-02 - E1 browser OSM ingest (`apps/web/lib/engine/osm/`)

Scope: everything under `apps/web/lib/engine/osm/` (new). No other file was
touched except `DECISIONS.md` (append) and this handoff doc. In particular,
`packages/contracts/schema/*.json`, `apps/web/lib/contracts.ts` and
`services/bake/app/contracts.py` were **not** touched -- see "Contracts"
below for why, and `[V3-P2-E1]` in `DECISIONS.md` for the verified reasoning.

## 1. Module map

| File | Purpose |
|---|---|
| `sha1.ts` | Pure-JS SHA-1 hex digest (sync) and the `[0,1)` unit-interval reduction the height jitter uses. |
| `tmerc.ts` | WGS84 ellipsoidal UTM forward/inverse, Kruger n-series to order n^6 (Karney 2011, the same series PROJ's `etmerc` computes). |

| `geometry.ts` | Dependency-free 2D polygon toolkit: area/centroid (with/without holes), orientation, Douglas-Peucker simplify (ring and open path), snap-to-grid, Sutherland-Hodgman convex clip, a Greiner-Hormann polygon union/intersection with documented fallbacks, ring assembly from line segments. |
| `heights.ts` | Tag parsing (`parseLengthM`, `parseLevels`), `resolveHeight`/`resolveHeightWith` (v3-tunable via `heightRulesFrom`), `roadWidthM`, `roadClass`, `classifyCoverage`. Mirrors `app/ingest/normalize.py`'s same-named functions exactly. |
| `presets.ts` | The six frozen presets, `cityName` read from `apps/web/lib/presets.ts`'s `PRESET_CITY_NAMES` (not duplicated). Replaces `GET /presets`. |
| `normalize.ts` | The pipeline: classify -> project -> hygiene (03's seven steps) -> crop -> emit. `sceneFromOverpass` is exported from here but re-exported (with the v3 heights param) from `scene.ts`. |
| `overpass.ts` | `buildQuery`/`bboxFor` (byte-identical to Python), `fetchOverpass` (mirror failover, backoff, cache, fails soft), `MemoryOverpassCache`/`IndexedDbOverpassCache`. |
| `scene.ts` | Public API: `sceneFromOverpass(raw, request, params?)` (pure) and `buildScene(request, params?, options?)` (network, fails soft). |
| `types.ts` | `EngineBuilding`/`EngineRoad`/`Rail`/`EngineSceneGraph`: additive superset types carrying name/landmark/rail/bridge/layer, since the frozen schema was not touched. |

## 2. Contracts: why nothing was regenerated

The brief asked for building name/landmark hints, a `rail` layer and
`bridge`/`layer` as "optional SceneGraph fields... regenerate contracts."
Before doing that, I checked what regenerating `services/bake/app/
contracts.py` would actually do to the existing Python test suite (not
assumed, verified with a real pydantic v2 model): any new `Optional` field
on `Building`/`Road`/`SceneGraph` is emitted as `null` by `.model_dump()`
even when the input never set it. `services/bake/tests/test_contracts.py
::test_scene_graph_dumps_fixture_verbatim_without_by_alias` does
`SceneGraph(**fixture).model_dump(mode="json") == fixture` with **no key
filtering** (unlike the analogous PrintParams tests, which explicitly
compare only the original example's keys) -- so regenerating would break
that pinned test for every committed SceneGraph fixture, in a file this
task does not own.

Given that, the schema stays untouched and `types.ts` defines
`EngineBuilding`/`EngineRoad`/`Rail`/`EngineSceneGraph` as **structural
supersets** of the frozen contract types (`Building & {name?, landmark?,
tourism?, historic?, wikidata?}`, etc.) -- assignable anywhere a plain
`SceneGraph` is expected, so `EngineInput.scene: SceneGraph` in
`lib/engine/types.ts` still accepts what `sceneFromOverpass` returns.
Promoting these into the frozen schema later is a one-line follow-up for
whoever owns `test_contracts.py`: extend that one test with the same
key-filter pattern the print_params tests already use.

## 3. Parity (measured, not aspirational)

Ground truth for every number below was generated by actually running the
Python reference (`uv run python`, read-only, no files written under
`services/bake`) against the committed fixtures, not assumed. Against
`fixtures/chicago-scene.json` (Python's real `/scene` output) on the
committed `tests/fixtures/overpass-chicago-loop.json` (16k elements, sha1
`a4e5375818f309940313e0ac08b8ebb88c615f9e`):

| Layer | TS | Python | |
|---|---|---|---|
| buildings | 992 | 994 | 99.8% |
| roads | 5439 | 5443 | 99.9% |
| water | 41 | 42 | |
| green | 709 | 711 | |
| trees | 5762 | 5762 | exact |

First ten buildings sorted by id: the id list matches Python's exactly.
Net footprint area (ring minus holes) and height: 8 of 10 are bit-exact or
within 1e-6 m; one (`r1870546`) differs by ~0.06 m^2 out of ~26,000
(Douglas-Peucker vs GEOS's topology-preserving simplify picking a different
near-tolerance vertex on a large ring); one two-part relation
(`r17460539`/`r17460539-1`) splits into the same pair of areas as Python but
the two pipelines assign the `-1` suffix to different parts (both parts are
individually correct as a set). `normalize.test.ts` pins these exact,
measured numbers with the two known exceptions documented inline, not a
blind `toBe(994)`.

Two real bugs surfaced and were fixed while chasing this (both have
dedicated regression tests): a sign error in the Sutherland-Hodgman
line-intersection formula (collapsed building count from ~994 to 656 before
the fix), and a naive bounding-box-overlap-area heuristic that badly
over-merged adjacent, non-overlapping footprints (165 spurious merges vs
Python's real 88; replaced with an inclusion-exclusion estimate through the
same Greiner-Hormann union code, landing at 91).

Full detail, including the collinear-edge/vertex-on-edge Greiner-Hormann
degeneracy and the touching-vertex fix for the water/green dissolve, is in
`DECISIONS.md`'s `[V3-P2-E1]` entries.

## 4. Performance

Chicago fixture (16k elements): **496 ms warm** in Node (budget: 1.5 s).
The Lake Michigan `natural=water` relation in that fixture has a 47,431-
vertex ring; without two targeted fixes (pre-clip water/green rings to a
padded square before the O(n^2) dissolve stage, and an O(n) approximate
farthest-pair split in `simplifyRing` above 500 vertices) this stage alone
cost ~2.6 s. Buildings and roads never approach that vertex count, so
neither fix touches the pinned building-area parity above.
