# DECISIONS

Append-only. Format: `- [phase] decision, one line`.

- [P0] Dev host is Windows 11 with no Docker and no make preinstalled; installed GNU make 4.4.1 via winget (ezwinports.make) and Python 3.12.13 via uv so the spec's `make` gates run literally.
- [P0] `make up` detects `docker compose`; when absent it starts both services natively (uv run uvicorn + npm run dev) in the background and waits for /health. docker-compose.yml is still shipped for Linux/CI.
- [P0] Python dependency management is `uv` with `pyproject.toml` + `uv.lock` (Python 3.12 pinned by `.python-version`); web uses plain `npm` with a committed `package-lock.json`.
- [P0] Agent definitions use the models named in 05 (sonnet/opus); the orchestrator session itself runs on the session model.
- [P0] Frame width is fixed at 6 mm (04 Stage 2) and is not a user slider; it enters the scale formula only when `frame` is on.
- [P0] `rotation_deg` lives on SceneRequest (server-side crop), so rotation changes trigger a /scene refetch like location and radius do; all other params are client-only.
- [P1] SceneRequest: `lat`, `lon`, `radius_m`, `rotation_deg` are required with no schema default (02 lists only `preset_id` as optional); `radius_m` is bounded [250, 3000] and `rotation_deg` [0, 360] per 01's editor table.
- [P1] BakeResult gains two ADDITIVE fields per orchestrator pre-approval: `progress` (number 0..1, optional, default null) and `error` (string or null, optional, default null, names the failing validator). Both are anyOf[T, null] in the schema, Optional in Pydantic, `T | null` (`?:`) in TS.
- [P1] SceneGraph.roads[].class enum is exactly `motorway|primary|secondary|residential|service|path` per 02's contract text, a smaller set than 03's Overpass highway-tag list (trunk, tertiary, unclassified, pedestrian, footway). geo-ingest must bucket the extra OSM highway tags into these six (e.g. trunk->primary, tertiary/unclassified->residential, pedestrian/footway->path) when it implements normalize.py.
- [P1] PrintParams ranges are expressed as fractions matching 02's example values (e.g. `small_scale` 0.5-1.5, `road_scale`/`large_scale` 0.5-2.0, `terrain_exaggeration` 0.0-3.0), not the 0-100 percents shown in 01's prose table. `nozzle_mm` has no 01 slider; bounded [0.1, 1.2] mm as a physical sanity range, default 0.4 per 02.
- [P1] Pydantic field names that collide with JSON keys that are not valid Python identifiers use an alias: `BakeFiles.file_3mf` (alias `"3mf"`) and `Road.class_` (alias `"class"`), with `populate_by_name=True` on every generated model. Any phase serializing these to JSON must call `model_dump(by_alias=True)` (or `by_alias=True` in FastAPI response models) or the wire JSON will show `file_3mf`/`class_` instead of `3mf`/`class`.
- [P1] packages/contracts/gen_py.py and gen_ts.py are hand-written, stdlib-only (no deps) generators that understand exactly the JSON-Schema shapes used by these four schemas ($ref/$defs, enum, anyOf[T,null], type:[T,"null"], array w/ minItems==maxItems as a fixed tuple, object). They are not a general JSON-Schema compiler; extending schema/*.json with a new construct (e.g. a second level of $ref indirection across files, oneOf, allOf) requires extending the generators too.
- [P1] fixtures/chicago-scene.json was authored via a short deterministic Python layout script (grid of 40 buildings in 5 rows x 8 cols, procedurally correct CCW/CW ring winding) rather than typed by hand coordinate-by-coordinate, then verified against scene_graph.json (jsonschema) and round-tripped through the generated Pydantic models; the script was deleted after generating the fixture. It is a hand-authored fixture in the sense required (not fetched from Overpass); geo-ingest will later regenerate it from real data.
- [P1] `make validate` resolves a relative `FILE`/positional-arg path against `$PWD` (the repo root at invocation) into an absolute path before `cd services/bake`, so both `make validate FILE=artifacts/x.3mf` and `make validate artifacts/x.3mf` (per G3's exact command) work when run from the repo root, even though the recipe internally cd's into services/bake per 02/05's literal target shape.
- [P1] On this Windows Git Bash host, bash's `$!`/`kill -0` do not reliably reference real Windows PIDs (verified empirically: a captured `$!` did not match any `tasklist` entry, while the actual uvicorn/npm processes were listening under different PIDs). `make up`'s native path therefore starts each service, then (when `taskkill` is on PATH) discovers the real PID by scanning `netstat -ano` for the service's port and records that PID in `.run/*.pid`; `make down` then `taskkill //PID <pid> //T //F`s it. POSIX hosts (no `taskkill`) keep the plain `$!` capture and `kill`. Verified end-to-end on this host: `make up` (idempotent on rerun) -> both curls 200 -> `make down` frees both ports.

- [P2] Overpass bbox: 03's 15% margin is applied to the rotated crop's actual reach, `half = radius_m * (|cos t| + |sin t|) * 1.15` with `t = rotation_deg mod 90`. That is literally `1.15 * radius_m` for the five presets at rotation 0/90/180/270; without the reach factor the 29 deg New York crop would come back with empty corners (it needs 1.36 x radius before any margin). The bbox is built by projecting the metric square's edges (16 samples per edge, not just corners) back to WGS84, so the UTM edge bulge cannot clip data.
- [P2] `rotation_deg` convention: the geometry is rotated counter-clockwise by `rotation_deg` about the origin, i.e. the compass bearing `rotation_deg` (deg CW from north) ends up pointing +y in the model. New York's 29 deg therefore squares the Manhattan avenue grid to the plate. web-editor's picker overlay must draw the crop square rotated CW by the same angle.
- [P2] Projection runs *before* the seven hygiene steps (every 03 tolerance is metric: 0.25 m simplify, 0.5 m centroid dedupe) and the rotation is folded into the same vectorized numpy/pyproj pass. Rotation is rigid and every hygiene op is rotation invariant, so 03's "rotate, then clip to the axis-aligned square" is preserved exactly; only the clip happens after hygiene.
- [P2] Hygiene step 7 ("union overlapping building footprints that touch") is implemented as: union only footprints whose *interiors* share area greater than `max(0.25 m2, 2% of the smaller footprint)`. Buildings that merely share a wall (a Paris block, 2905 buildings, 303 with courtyards) keep their own heights - merging them into one prism at the tallest member's height would flatten the skyline, and 04's assemble unions them anyway.
- [P2] Merged groups (dedupe step 6 and union step 7) keep the largest-area member's id and geometry footprint, the tallest member's `height_m` + `height_source`, and the minimum `min_height_m`. Emitted ids stay unique per scene: `w<id>` / `r<id>` / `n<id>`, with a `-1`, `-2` suffix when the crop splits one way into several parts.
- [P2] Polygons smaller than 1.0 m2 (after hygiene and again after the crop) and road fragments shorter than 1.0 m are dropped as print-scale noise; 03's step 1 "zero area" test stays literal (`area <= 0`) and is separate from this threshold.
- [P2] Coverage: 03 does not say what `building_count >= 150` with under 4% footprint area is; it is classified `sparse` (only count AND area together earn `good`). All six presets measure `good`.
- [P2] Height inference extensions, all inside 03's rule order: rule 1 also reads `building:height` (same meaning, same `height_source == "tag"`), rule 3 also honours an explicit `min_height` tag, and the rule-4 table adds `garages` (3 m) next to `garage`. `building=no`/`building=false` is not a building. Jitter is `sha1(osm_id)[:8]` mapped uniformly into +/-6%.
- [P2] Water and green are dissolved per layer with `unary_union` after hygiene (an OSM relation and its member ways both come back in one response, so undissolved layers print coincident slabs); buildings are never dissolved that way, they go through steps 6 and 7 so each keeps its own height.
- [P2] Roads are simplified with the same 0.25 m tolerance as polygons, clipped by intersection, and MultiLineString results are split into separate entries. Width is `width` tag, else `lanes * 3.5`, else the 03 table keyed by the ORIGINAL highway tag; `class` follows the [P1] mapping.
- [P2] Emitted coordinates are rounded to 1 mm (3 decimals in meters) with consecutive duplicates removed and no repeated closing vertex; a ring whose rounded form is not a valid `Polygon(ring, holes)` drops its holes, and if it is still invalid the part is dropped (never observed on the six fixtures: 0 invalid out of 16 828 footprints).
- [P2] POST /scene caches: an in-process LRU of 6 SceneGraphs (~14 MB each, so the six presets stay warm; measured 7-12 ms warm, 32 ms from disk, 1.7 s cold from a fixture) plus `artifacts/cache/scene/<sha256-of-request>.json` with a 24 h mtime TTL. The parsed raw Overpass cache holds only 2 responses because a parsed fixture is 35-85 MB in memory.
- [P2] `preset_id` semantics on POST /scene: a request that names a preset AND matches its lat/lon/radius/rotation is served from the committed fixture with the network disabled; a request that names a preset but has edited values is no longer that preset and takes the normal cache-then-network path; an unknown `preset_id` is a 400. Error mapping: `OverpassOffline` -> 503, `OverpassUnavailable` / `FixtureMissing` -> 502 with the reason in `detail`.
- [P2] `FRAMECRAFT_OFFLINE=1` (set by `services/bake/tests/conftest.py` for the whole suite) makes every Overpass network path raise `OverpassOffline`, so the tests provably run from the committed fixtures; the preset /scene test additionally monkeypatches `overpass._post` to a raising sentinel and asserts it was never called.

- [P2-fix] Overpass bbox: the sampled ring is built in the ROTATED frame at `radius_m * 1.15` and `LocalFrame.to_wgs84` un-rotates it, which is what produces DECISIONS [P2]'s `(|cos t| + |sin t|)` reach; the old code multiplied the ring by that reach as well, so the fetched window was `1.15 * r * reach^2` (New York 1941 m instead of 1407 m half-extent, ~2x the area and ~2x the timeout risk). `unrotated_reach_m()` documents the invariant and the test asserts the measured half-extent is within 2% of `1.15 * 900 * (cos29 + sin29)`. Only the New York query text changes; its fixture was re-fetched (new sha1 `f41c2522...`, 12.9 MB / 16 998 elements, down from 20.6 MB / 28 130) and `presets-index.json` regenerated. The other five sha1s are byte-identical, and NY's normalized scene is unchanged (2 683 buildings, same height_tag_ratio), i.e. the discarded 40% of the response was all outside the crop.
- [P2-fix] An Overpass HTTP 200 whose body carries a `runtime error` remark (documented for query timeout and out-of-memory) - or any remark next to an empty `elements` list - is a FAILED ATTEMPT, not an empty city: `overpass.fatal_remark()` detects it, `_parse` raises `OverpassUnavailable(switch_mirror=True)` for the timeout/OOM shapes so the loop falls back to the kumi.systems mirror exactly as a 504 does, and the fixture file is written only after `_parse` accepts the body. `_parse` now runs INSIDE the per-attempt `try`, so a proxy's HTML 200 also gets the retry policy instead of escaping on attempt 1. `load_raw` additionally refuses to serve an already-cached error body (raises `FixtureMissing` when the network is off, re-fetches when it is on), because the fixture cache is consulted before the network and has no TTL.
- [P2-fix] A `way` that is the `outer` member of a `building` multipolygon relation is dropped as a standalone building during classification (03 step 6 anticipates that both come back). Old-style OSM tagging repeats `building=*` on that way, the way has no inner rings, and it used to win - through step 6's dedupe below 5% and through step 7's union above it - which printed the courtyard solid (london-city r1439717 Haberdashers Hall was emitted as w100835946, 1 556 m2 with 0 holes, instead of 1 213 m2 with 1 hole).
- [P2-fix] SUPERSEDES the step-6 half of the earlier [P2] "merged groups keep the largest-area member's id and geometry" line: dedupe now compares HOLE-LESS (exterior) areas, so a holed relation still matches its outer way, and the group keeps the geometry AND id of the member with the most interiors (largest area breaks the tie). Step 7's union is unchanged and still keeps the largest-area member's id. Heights still come from the tallest member.
- [P2-fix] Geometry is snap-rounded onto the 1 mm emission grid with `shapely.set_precision(g, 0.001)` (GEOS topology-repairing) at the end of `_clean` and again after the crop, i.e. BEFORE validity is judged, and `_rings_of` now repairs a still-invalid rounded polygon with `make_valid` and emits its largest polygonal part instead of dropping the holes or the part. Before, `bad` only ever collected strokes that were TOO THIN, so a bake that requested every ornament and cut none reported `lettering PASS 0.000 mm stroke` and gate-v2's `lettering +PASS` grep accepted it (v2-07 audit, finding 2). Every value is chosen to make the expansion at least as LONG as any real one, and a longer string is harder to fit, never easier, so "this context says the piece is not refused" implies the real one is not refused: the expected-piece count can only ever UNDER-count.
